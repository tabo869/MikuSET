# 詳細設計書: `src/components/MusicManager.tsx`

## `function MusicManager()`

### 1. 概要
アプリケーションの 2D フロントエンドおよび UI ステート管理を担当し、タイトルの楽曲選択からプレイ、リザルト画面までの一連のユーザーフローを制御します。

### 2. UI ステートマシン仕様

#### 2.1. 状態遷移フロー
- **[Idle / Title]**: 全体の初期状態。`songs.ts` に定義された楽曲リストをカード形式で表示し、ユーザーが選曲するのを待機。
- **[Loading / Ready]**: 曲が選択され、TextAlive からのデータ読み込み (`isVideoReady`) を待っている状態。読み込み後は「START」ボタンを表示し、カメラテストを許可。
- **[Countdown]**: ユーザーが「START」を押下した直後。3, 2, 1, GO! のカウントダウンを行い、終了時に楽曲を再生し、`state.isPlaying` を `true` にする。
- **[Playing]**: 演奏中。プレイ画面の HUD や一時停止、中断ボタンを表示。
- **[Result]**: 楽曲の最後まで到達した場合。`useGameState` から最終成績を読み出し、スコア、コンボ、判定内訳などを集計・表示し、タイトルへ戻る。

### 3. データ連携仕様

#### 3.1. 楽曲解析とデータ展開
`TextAlive App API` から取得した歌詞データの `Word` および `Char` リストを、パフォーマンス上の理由からグローバルな定数（`window.__mikusetWords` 等）として展開し、`NoteManager` や `PhraseDisplay` が同期して参照できるように調整を行います。

#### 3.2. キャリブレーションウィザード (`CalibrationWizard`)
- **ステップ**: 1. 左上、2. 右上、3. 右下、4. 左下の 4 点を順番に指定させる。
- **目的**: 実際のカメラ画角における手の稼働限界を定義し、それを Three.js 空間のプレイエリアに合わせる。
- **永続化**: 完了したデータは `GameState` を通じてアプリ全体で共有される。

### 4. リザルト集計ロジック
- スコアに応じたランク表示（S, A, B, C）の閾値判定。
- ヒット率（HIT / Total * 100）の算出。
- 全体の判定結果をグラフ表示する `ResultScore` コンポーネントへのデータ注入。
