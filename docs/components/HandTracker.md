# 詳細設計書: `src/components/HandTracker.tsx`

## `function HandTracker({ handsDataRef }: { handsDataRef: BothHandsDataRef })`

### 1. 概要
Web カメラからの映像ストリームを MediaPipe AI モデルで解析し、プレイヤーの両手の 3D 座標をリアルタイムで抽出・共有するための非表示エンジンレイヤーです。

### 2. 推論エンジンの設計仕様

#### 2.1. CPU 推論の採用根拠 (`delegate: 'CPU'`)
- **設計判断**: GPU 推論は同期的なデータのやり取りによってブラウザのメインスレッドをブロックし、Three.js の描画（60fps）に深刻なスタッター（カクツキ）を引き起こすことが実証されています。
- **解決策**: WASM（WebAssembly）を用いた CPU マルチスレッド推論を採用することで、描画ループと推論処理を並行させ、安定したフレームレートを維持します。

#### 2.2. カメラ設定の最適化
- **解像度**: 推論コストを最小化するため、入力映像を **320x240 @30fps** に固定します。
- **ミラーリング**: プレイヤーが鏡を見ている感覚で直感的に操作できるよう、映像および抽出座標を水平反転して処理します。

### 3. 座標解析ロジック仕様

#### 3.1. 逆サイドガード (Cross-over Guard)
- **課題**: カメラ画角内で一瞬手が重なったり隠れたりした際、MediaPipe が左右の手を誤って逆転させる現象。
- **仕様**: 
  - カメラ座標系（0.0〜1.0）において、左手は X > 0.5、右手は X < 0.5 の領域に存在することを原則とする。
  - 前フレームからの移動距離が一定の閾値を超えるような「瞬時の左右入れ替わり」を検知した場合、そのフレームを破棄し、状態を維持することでバトンのジャンプを防止する。

#### 3.2. キャリブレーション・マッピング
- ユーザーが設定した `calibrationData` (四隅の生座標) を「操作有効領域」の 100% 矩形として扱い、そこから Three.js のワールド空間座標へと線形変換を行います。
- 領域外に指が出た場合も、プレイ継続性のためにエッジでクランプ（固定）し、指揮棒が画面外へ見失われないようにします。

### 4. 共有データ (`handsDataRef`) の更新
- React の State アップデートを一切介さず、`requestAnimationFrame` ループ内で `handsDataRef` (Mutable Ref) を直接書き換えます。これにより、1秒間に 60 回の頻度で行われる座標更新が原因で UI 全体が再描画されるコストを完全に排除します。
